GR00T N1.6 on a Unitree G1: 61% whole-body pick-and-place, reproduced

The released GR00T N1.6 G1 checkpoint, evaluated over 3 seeds x 100 episodes in simulation, lands at 0.610 against the repository's 0.58 (pass band 0.43 to 0.73). Videos below are real rollouts, successes and failures.

The released checkpoint nvidia/GR00T-N1.6-G1-PnPAppleToPlate (HF revision 897d0313) was evaluated with the official, unmodified rollout script at the Isaac-GR00T N1.6 release commit 4e62473. The task is a whole-body loco-manipulation episode on a simulated Unitree G1: pick up the apple, walk left and place the apple on the plate. An episode counts as a success if any step reports success. The result reproduces the repository-reported 58% (+/-15% expected variance) and passes the gate check.

Why this baseline exists

B01 is Foundation B of the project: the manipulation policy that the ATLAS language-embedded Gaussian-splat navigator (B02) will later hand off to. A reproduction on released weights is the first checkpoint of the research chain; only a finalized B01 unlocks B02.

06

Independent verification

A separate verifier agent re-derived the result from raw evidence (verdict pass, 2026-10-05). It recomputed the sha256 of every log, recounted the official results: lists (62T/38F, 59T/41F, 62T/38F), confirmed that the official success rate: print equals the wrapper's SUMMARY line in each log, checked that git diff between the seed-0 and rerun tags touches only the host-RAM sampler in run_seed.sh, and confirmed that the fidelity tool reports zero changed files against upstream.

Disclosed caveat

The three seeds are split over two sub-versions (seed 0 in b1.1, seeds 1-2 in b1.2). The verifier judged this acceptable because code, flags, checkpoint and seeds are identical; the gate's own check covers b1.2 only.

07

Deviations from the README protocol

  1. 100 episodes per seed instead of the README's 10, because 10 episodes give a binomial standard error of about 15 points.
  2. Host and port flags added to the client (the README command omits them; the script asserts one of the two is set).
  3. Seeding wrappers outside the vendored code; evaluation logic untouched.
  4. Host-RAM sampler added from tag v0.1.52 (measurement only).
  5. 64 GB to 160 GB RAM for seeds 1-2 after two OOM kills (see b1.2).
  6. Seeds split across two sub-versions (above).
  7. GPU models differ (3090 / 3090 / A6000); physics is CPU-bound so this should not matter, and the per-seed rates agree within sampling noise.
  8. Code commit: only the release commit 4e62473 was run; the later n1d6 head was not. Integration must use this commit's preprocessing.
  9. Videos are written to /tmp by the official script and moved after the rollout; this does not affect results.
