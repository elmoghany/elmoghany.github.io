What the harness is

The closed-loop harness g1cl-v1 is the simulator side of the project: a Unitree G1 explores a house, maps it, navigates to an object named in language and hands off to a manipulation policy; one EPISODE line is logged per episode. B02's closed-loop band is measured in it, with ATLAS and a control arm that picks frontiers at random.

simulator
Isaac Sim 6.0.1 + Isaac Lab 3.0.0-beta2.patch1; task framework Isaac Lab-Arena 0.3.0
robot
Unitree G1 (29-DoF + 3-finger hands) through Arena's whole-body-control embodiment; navigation commands go to the fixed lower-body controller
sensing in render mode
head RGB-D rendered at 640x480, processed at 256x160, 10 Hz, ground-truth base pose; physics at 200 Hz, control 50 Hz
scenes
dev ProcTHOR houses from MolmoSpaces (train_4010, 1355, 4595, 2514, 6537, 8597); 36 explore-tier tasks for the B02 band; no validation or test scene is used by B02
episode
navigation budget 180 s of simulated time, then hand-off; success stages find, reach, grasp
Status

The harness was marked sim-ready after a closed-loop smoke test passed all its pre-registered criteria (job 10753). Pre-record checks and throughput jobs were running at the last hand-off entry. No band episode has been recorded, and no closed-loop video exists: smoke runs did not save frames, and frame dumps are off by default.

02

Fix: the G1's own torso in the head camera (before / after)

Problem. The G1's head camera sees the robot's own body: 13.5 to 14.4 percent of depth pixels at the start of an episode, a fact fixed by geometry (the Jackal in the ATLAS paper never sees itself). The ATLAS planner treated those pixels as obstacles: at the start of an episode 649-1,315 non-ground Gaussians sat inside the start sphere, every one of them 'self-like' (about 0.28 m from the camera and 0.23-0.29 m below it, tiny surfels of radius 1-2 mm, i.e. inside the torso), 640-870 of them inside the 0.3 m agent radius.

Fix (round 6). The harness adds an instance-segmentation annotator to the same head camera and sets depth to 0 wherever the pixel belongs to any prim under the robot, before any agent sees the frame. RGB, intrinsics, the ground rule and the planner are unchanged, and the mask is identical for every agent (fairness rule).

Fix: the CRLF crashes

Windows line endings were saved into shell scripts that run inside Linux jobs. Bash then dies parsing the script itself. Two jobs were lost this way within an hour.

job 10874 (pre-record checks), 158 s

atlas_closed_loop.sh, band.py and shim_node.py had been saved with CRLF; the container session died at once (set: pipefail: invalid option name), the bridge never listened and all three episodes ended as a crash at step 0 (connection refused). 0.85 GPU-h lost.

fix v0.2.219

Scripts back to LF; isaac_env.sh now fails any job immediately (SIMENV CRLF line endings in: ..., exit 3) if any sim/scripts/*.sh contains a carriage return.

job 10939 (equivalence test), 10 s

The guard cannot protect the script that sources it: the newly added atlas_thru.sh and thru_check.py had CRLF and bash died before reaching the guard.

fix v0.2.223

Rule from now on: before every save, scan sim/scripts/*.sh, sim/atlas/*.py, sim/harness/*.py for carriage returns, strip them and run bash -n. The test was resubmitted as job 10979.

04

Fix: a planner hang that ate a smoke job

The first R6.7 smoke (job 10631) timed out. The official ATLAS A* has a 0.3 s search budget measured with rospy.Time.now(); under lockstep simulation the simulated clock is paused during the planner callback, so the budget never fires, and an unreachable frontier made the search run unbounded (more than 30 minutes). The fix (v0.2.201) measures the budget on wall-clock time, keeping the official 0.3 s value and the official best-so-far recovery path. In the follow-up smoke the budget fires on 21 of 30 plans (70 percent), which the director accepted as the expected behaviour of the anytime-style planner (decision rounds 8 and 9); every fired plan still returned a trajectory.
