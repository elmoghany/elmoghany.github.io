What this project is

The goal of atlas-manip-humanoid is a single pipeline for a humanoid robot: explore and map an unseen indoor scene, localise and navigate to an object named in language, then manipulate it, scored end to end in closed-loop simulation. The method blends two foundations:

A · ATLAS Navigatortask-driven, language-embedded Gaussian-splat mapping + planning (arXiv 2502.20386, BSD-3)
+
B · manipulation policyGR00T N1.6 on a Unitree G1 (B01)
→
find, reach, grasphumanoid, Isaac Sim 6.0.1 + Isaac Lab-Arena

Before anything new is built, each foundation is reproduced as a numbered baseline, so every later claim has a trustworthy starting point. ATLAS's headline results are single real-robot runs with no released data, so it is reproduced in proxy mode: component targets (open-vocabulary 3D segmentation, GPU memory) plus a pre-registered band for the closed-loop behaviour in our own simulator. Every band was written down before any measurement.

Honest status

B01 is final. Everything under B02 is preliminary and unverified: the scorer was validated against an independent anchor (ConceptGraphs reproduced its published numbers, the ground-truth oracle passed), the ATLAS software was containerised and verified on GPU, and the closed-loop simulation harness is marked sim-ready. But the ATLAS Replica segmentation score (mIoU 0.003) is far below its pre-registered band (0.12 to 0.19), and the cause is an open investigation, not a settled result.

How results are judged

  • Pre-registered targets. Each baseline has a target file with a value, a tolerance band and a protocol, frozen before the first measurement. Edits after that need a written decision round.
  • One change per sub-version. Every attempt is logged as bK.X with what changed, the result and the run ids, and tagged in git.
  • Independent verification. A separate verifier agent recomputes results from raw logs before a baseline is finalized.
  • Out-of-band results are not recorded as passes. They are reported as misses and investigated.
