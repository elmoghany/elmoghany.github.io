What this version is

The gate numbers each attempt, and a record made after an attempt is logged lands in the next sub-version. The single ATLAS row that was recorded, B02-b2.6-score-s0-10172 (kind checkpoint, seed 0, code tag v0.2.166, log sha256 495bf96c...), therefore carries the id b2.6, although it is the scoring result described under b2.5. The recording followed the evaluator's rule: record per the target with real logs and let the gate show the segmentation miss.

Why the gate says seeds = 0

This is expected behaviour, not a recording fault. In proxy mode the check counts only --kind proxy rows for the components, seeds and sim band. The checkpoint row feeds only the checkpoint stage, which needs all eight checkpoint metrics: the six scorer preconditions pass, but ATLAS miou (0.003 vs 0.155 +/- 0.035) and miou_rel_cg (-0.181 vs -0.01 +/- 0.04) fail, so the stage stays PENDING, and the gate then refuses every proxy row while it is pending.
